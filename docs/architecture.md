# 구조와 모듈

이 서비스가 어떤 부품으로 되어 있고, 각 부품이 왜 있으며 무엇을 하는지 정리한 문서다.

## 한눈에 보기

```
설문 응답 ──▶ M1 survey.py ──(점수·성향)──┐
                                           ▼
가격(yfinance) ─▶ data.py ─▶ M2 frontier.py ─▶ build_data.py ─▶ data/*.csv ─▶ app.py (Streamlit)
                              M3·M4 backtest.py ┘   (미리 계산)              (화면은 읽기만 함)
                              course/ 수업 모듈 ┘
```

- **계산은 미리, 화면은 읽기만.** 교수님 피드백("슬라이더는 미리 계산한 근사값으로")에 따라 프론티어 100개 지점과 모든 백테스트를 `build_data.py`가 한 번에 계산해 `data/`에 저장한다. 앱은 CSV를 읽어서 보여주기만 하므로 슬라이더를 움직여도 바로 반응한다.
- **수업 모듈 위에 쌓기.** 비교 모형(MVP·최대샤프·RP·MD·EW)의 비중과 백테스트 기준가는 수업 코드(`course/`)로 계산한다. 결과를 수업 내용으로 설명할 수 있게 하려는 것이다.

## 파일별 역할

| 파일 | 제안서 모듈 | 하는 일 | 왜 있나 |
|---|---|---|---|
| `core/config.py` | 공통 | 투자 대상 3가지(미국 ETF, 한국 ETF, 대형주 20종목)의 종목 목록과 계산 설정(연율화 250, 연말 리밸런싱, 거래비용 10bp, 추정 기간 1년/3년, 비중 상한 40%) | 숫자 설정이 여러 파일에 흩어지면 바꿀 때 하나를 빠뜨림. 한 곳에서 관리 |
| `core/data.py` | 공통 | yfinance로 수정종가(어제 종가까지)를 받아 `data/prices_{시장}.csv`로 저장. 공통 거래일만 남기고, 대형주 버전은 미국 주식을 원화로 환산 | 앱을 켤 때마다 받으면 느리고 결과가 바뀔 수 있음. 최신으로 바꾸고 싶을 때만 앱의 버튼으로 업데이트 |
| `core/survey.py` | **M1 투자성향 진단** | 7문항, 보기별 점수(① 5점 … ⑤ 1점), 성향 판정, 점수 → 프론티어 위치 변환 | 성향 이름만으로는 프론티어의 어느 점인지 정해지지 않아서 점수를 위치로 바꾸는 규칙이 필요 |
| `core/frontier.py` | **M2 효율적 프론티어 엔진** | 프론티어 100개 지점, 성향 위치별 비중, MVP·최대샤프·RP·MD 한 시점 계산, 위험기여도 | 수업 `efficient_frontier_plot.py`와 같은 최적화를 쓰되 지점 수·실패 처리를 고침 ([문제와 해결](issues-and-solutions.md#d3) 참고) |
| `core/backtest.py` | **M3 추천·비교 + M4 성과 리포트** | 매년 말 리밸런싱 백테스트. 비교 모형은 수업 함수로, 내 포트폴리오는 매년 프론티어를 다시 그려 같은 성향 위치를 보유 | 추천 비중이 과거에 실제로 어땠는지 검증(제안서의 "과거 성과로 검증") |
| `course/quant_model_modules.py` | 수업 모듈 | 7주차 모형 함수 중 쓰는 것만 옮김(EW, MD, 최대샤프, MVP, RP) | 수업 코드 그대로 비교 모형을 계산하기 위해 |
| `course/cal_nav_module.py` | 수업 모듈 | 9주차 기준가(NAV) 계산과 성과지표. 소르티노 추가 | 거래비용을 반영한 백테스트, 성과지표표 |
| `build_data.py` | 공통 | 위 모듈을 돌려 화면에 필요한 값을 전부 미리 계산·저장 (약 1분) | 슬라이더·토글 반응 속도 |
| `app.py` | 화면 | 설문 화면 → 대시보드 | 4개 모듈을 하나의 프로토타입으로 묶음 (교수님 피드백) |

## 화면 구성 (`app.py`)

**1단계: 설문 화면**
- 7문항을 다 답해야 "결과 보기"가 켜진다. 답하는 동안 점수와 성향이 실시간으로 보인다.

**2단계: 대시보드** (위에서부터)

| 섹션 | 보여주는 것 | 쓰는 데이터 |
|---|---|---|
| 상단 슬라이더 | 위험 수준 조절 (왼쪽 안정, 오른쪽 공격). 처음 위치는 설문 점수 | 프론티어 100개 지점 |
| 1. 이렇게 나눠 담으세요 | 성향 카드, 자산군 도넛, 종목별 투자 금액, 쉬운 말 지표 4개, 한 줄 요약 | 프론티어 지점의 비중 + 같은 위치의 백테스트 |
| 2. 과거에 이렇게 투자했다면 | 시작 시점(10·5·3·1년 전)별 금액 그래프, 해마다 수익/손실 | 백테스트 기준가 |
| 3. 위험을 올리면 무엇이 바뀌나 | 효율적 프론티어(성향 구간 색칠), 위험 수준별 비중(자산군별/종목별) | 프론티어, ETF별 통계 |
| 4. 다른 투자 방법과 비교 | 최종 금액, 최대 하락 막대 + 최대샤프 순위 | 비교 모형 백테스트 |
| 5. 자세히 보기 (접힘) | 성과지표표, 연도별 수익률, 하락장 구간, 방법별 비중·위험기여도, 연도별 비중 변화, 상관계수, 용어, 계산 가정 | 전부 |

**사이드바 설정**

| 설정 | 바뀌는 것 |
|---|---|
| 투자 대상 (미국 ETF / 한국 ETF / 대형주 20종목) | 모든 숫자. 바꾸면 화면 맨 위로 이동 |
| 자산별 비중 상한 40% | 추천 비중과 백테스트 (상한을 건 프론티어로 바뀜) |
| 과거 성과 추정 기간 (직전 1년 / 3년) | 과거 성과와 비교만. 추천 비중은 그대로 |
| 투자금 | 금액 표시 |
| 데이터: 최신 데이터로 업데이트 | 가격을 새로 받아 모든 값을 다시 계산 (아래 참고) |

## 핵심 규칙 세 가지

### 1) 성향 → 프론티어 위치
- 위치 = (점수 − 7) ÷ 28. 0은 MVP(왼쪽 끝), 1은 최고 수익률 끝이다.
- 위치는 **변동성 기준**이다. 목표 변동성 = MVP 변동성 + 위치 × (끝 변동성 − MVP 변동성).
- 성향 경계는 10.5점, 24.5점이다. 위치로 바꾸면 안정추구형 0~0.125, 위험중립형 0.125~0.625, 공격추구형 0.625~1이다.

| 점수 | 성향 | 위치 |
|---|---|---|
| 7 | 안정추구형 | 0.00 (MVP) |
| 10 | 안정추구형 | 0.11 |
| 18 | 위험중립형 | 0.39 |
| 24 | 위험중립형 | 0.61 |
| 25 | 공격추구형 | 0.64 |
| 35 | 공격추구형 | 1.00 |

### 2) 슬라이더 = 미리 계산한 100개 중 가장 가까운 점
- 프론티어는 MVP 수익률부터 최고 수익률까지 100등분해 미리 풀어 둔다.
- 백테스트는 위치 0.05 간격 21개 × 비중 상한 2가지 × 추정 기간 2가지를 미리 돌려 두고, 슬라이더 위치와 가장 가까운 것을 보여준다.

### 3) 백테스트에 미래 정보를 쓰지 않음
- 리밸런싱 날짜 t의 비중은 t 종가까지의 데이터로 계산하고, t 종가에 매매한다고 가정한다.
- 1년/3년 추정 결과는 같은 시작일에서 비교한다(3년 기준 첫 연말).

## 데이터 업데이트

- 사이드바 맨 아래 "최신 데이터로 업데이트" 버튼을 누를 때만 갱신한다(자동으로 받지 않음).
- 버튼을 누르면 `build_data.build(시장, download=True)`를 세 투자 대상에 차례로 실행한다(1~2분). 가격을 어제 종가까지 받고 프론티어·백테스트를 다시 계산한 뒤, 캐시를 비우고 화면을 다시 그린다.
- **계산이 모두 끝난 다음에만 파일을 쓴다.** 중간에 인터넷이 끊기거나 Yahoo가 응답하지 않으면 에러만 보여주고, 기존 데이터는 그대로 남는다.
- 같은 일을 터미널에서 하려면 `.venv/bin/python build_data.py --download`를 실행한다.
- 날짜를 고정하고 싶으면 `config.END`에 날짜를 넣는다(그 전날까지 받음).
- **받아 오는 원본 데이터의 갱신 주기**: Yahoo Finance 일별 종가라 거래일마다 하루 1번 새 값이 생긴다. 우리는 "버튼 누른 날의 전날 종가까지" 받으므로 하루에 여러 번 눌러도 결과는 같다.
  - 미국 ETF·주식: 미국 장 마감(한국 시간 새벽 6시, 서머타임 땐 5시) 뒤
  - 한국 ETF·주식: 한국 장 마감(오후 3시 30분) 뒤. 다만 오늘 종가는 다음 날 눌러야 들어온다
  - 원/달러 환율: 하루 1개 값
  - 배당이 생기면 수정종가가 과거까지 다시 계산되어, 예전 기간 숫자도 조금 바뀔 수 있다
- 저장소의 `data/`를 건드리지 않고 시험하려면 `MPT_DATA_DIR=복사본폴더 streamlit run app.py`로 띄운다.

## 데이터 파일 (`data/`)

| 파일 | 내용 |
|---|---|
| `prices_{시장}.csv` | 일별 수정종가 (대형주는 원화) |
| `frontier_{시장}_cap{1.0,0.4}.csv` | 전체기간 프론티어 100개 지점: 수익률, 변동성, 샤프, 종목별 비중 |
| `stats_{시장}.csv`, `corr_{시장}.csv` | 종목별 연 수익률·변동성, 상관계수 |
| `bt_nav_{시장}_lb{252,756}.csv` | 비교 모형 5개 + 성향 위치 21개 × 상한 2가지의 기준가 |
| `bt_weights_{시장}_lb{252,756}.csv` | 리밸런싱 날짜별 비중 |

시장 코드는 `US`(미국 ETF), `KR`(한국 ETF), `STOCK`(대형주 20종목)이다.
